# 前端项目说明

本目录是电商智能客服 SaaS 的 Web 前端界面原型。当前使用模拟数据展示交互；接入后端时以 `docs/backend-integration.md` 和双方确认的接口契约为准。界面以需求文档 v1.8 的第一期 MVP 为基础，也包含用户后续提出的联系人、群聊和管理员中心等扩展原型。

最终目标是部署到服务器供授权用户通过 HTTPS 访问。`server.js` 只用于本地开发；前端资源保持相对路径，服务器需提供 `index.html`、`styles.css`、`pages/` 和 `src/`。正式鉴权、数据读写和消息外发由后端承担，不能依赖当前演示角色切换或浏览器内存状态。

## 文件与界面

| 文件 / 区域 | 作用 |
|---|---|
| `index.html` | 导航、顶部栏、账号菜单和共用弹窗；`#page-root` 是页面片段挂载点。 |
| `pages/*.html` | 按页面 ID 拆分的独立 HTML 片段；每个 `<section id="...">` 前保留中文界面注释。 |
| `src/load-pages.js` | 加载所有页面片段，再按顺序加载数据和交互脚本。 |
| `server.js`、`package.json` | 无依赖本地静态服务及 `npm run dev` 启动命令。 |
| `styles.css` | 全局设计变量、三栏工作台、表格、表单、弹窗与窄屏布局。 |
| `src/mock-data.js` | 演示客服会话、内部群聊和候选回复；正式接入时改用 API 数据。 |
| `src/app.js` | 页面切换与交互控制；关键后端对接点有 `TODO(API)` 注释。 |
| `src/admin-data.js`、`src/admin.js` | 企业管理员中心演示数据与界面交互：周期统计、员工对比、权限、分流资格、脱敏聊天记录和操作日志。 |
| `docs/backend-integration.md` | 页面所需数据、建议接口、状态与对接约束。 |
| `function.md` | 按页面和模块记录现有功能、本地演示范围及后端待补能力。 |

| 界面 ID | 使用角色 | 主要内容 |
|---|---|---|
| `workspace` | 客服、商家管理员 | 顶部接待状态、AI 辅助和指标栏；左侧切换“我的会话”和“联系人”。“我的会话”下分“处理中”“已结束”，分别显示数量；结束后归档到已结束，可只读查看历史消息。中间显示消息与回复，右侧显示客服辅助或群成员。 |
| `products` | 商家管理员 | SPU/SKU 商品列表、Excel/CSV 导入、索引与清洗状态。 |
| `knowledge` | 客服、企业管理员 | 统一展示商品、常见问题与公司快捷话术；客服可查看、搜索和测试，企业管理员可新增、编辑、启停与批量导入商品。读写均接后端，服务端再次校验角色和租户范围。 |
| `phrases` | 客服、商家管理员 | 个人 / 团队快捷短语；客服管理自己的个人短语，团队短语由商家管理员维护。工作台右侧可按范围与分类选用。 |
| `analytics` | 商家管理员 | 会话量、首次响应、候选采纳率和手打率。 |
| `admin` | 企业员工、企业内部管理员 | 全员可进入卡片首页；具体模块按权限开放，未授权点击弹出“暂无权限”并可申请授权。未授权统计不显示，角色切换清空不可访问内容。 |
| `settings` | 商家管理员 | 企业微信客服连接、欢迎语、离线回复、客服成员和店铺范围。 |
| `review` | 平台运营、平台超级管理员 | 采纳和编辑后发送的话术人工审核。 |
| `tenants` | 平台超级管理员 | 租户、店铺和成员范围配置。 |
| `account`、`login` | 所有用户 | 左下角账号卡片及账号中心；查看和修改头像、姓名、手机号，修改密码、退出登录，并展示账号配置状态、SSO 和受信设备。当前资料修改仅在页面会话中演示。 |

## MVP 边界

- 回复框快捷短语联想浮层随光标前关键词匹配个人与团队的启用短语，支持点击、方向键选择、Enter 填入与 Esc 收起；选中只替换匹配词，不自动发送。演示数据在 `src/mock-data.js` 的 `quickPhrases` 中，前端新增 / 编辑只更新页面内存；正式版本由服务端按租户及个人归属返回。
- 回复工具栏使用 SVG 图标，悬停或键盘聚焦显示名称：表情、截图、图片、视频、文件、快捷短语、商品链接、邀请下单。截图通过系统快捷键后粘贴，图片 / 视频 / 文件按会话暂存且一次选一个；邀请下单只回填演示商品链接，均需人工确认发送。
- AI 提供候选回复，客服选用或编辑后发送；欢迎语和离线回复才是首版自动发送场景。
- 新会话由服务端自动选择客服并推送到“我的会话”；工作台没有待接入池、抢单或退池操作。无人在线时由服务端保留并等待后续分配。
- 企业微信「微信客服」是首版业务渠道。订单、物流、退款、CRM 和其他电商平台接入属于后续阶段。
- 首版商品价格、库存与优惠来自导入快照，界面必须显示更新时间，候选回复不能把快照当成实时数据。
- 顶部订单、满意度和转化指标目前显示「—」，仅保留界面位置；真实数值要等对应业务系统与统计口径接入。
- 联系人分组是按用户要求提前加入的界面原型。团队成员、买家分组与黑名单的后端数据、权限和持久化仍需确定；当前新建分组、移动联系人只在浏览器内生效。
- 内部群聊是按用户要求增加的界面原型。新建群、群成员和群消息仅在本次页面会话内有效；它不使用微信客服外发接口、额度或 AI 候选。正式版本需另行确定群聊服务端接口和权限。
- 模拟角色切换只用于评审页面；正式版本的租户、店铺和角色权限必须由服务端校验。
- 管理员中心的指标、权限、分流参与资格和脱敏聊天记录均为本地演示。付款指标等待订单系统和归因口径；分流算法由后端确定。授予全部权限或单项权限只是浏览器内存中的状态，正式版本必须服务端鉴权、持久化并记录审计。
- 管理员首页及功能入口对企业员工开放；概览统计随员工对比 / 分流权限显示，其他模块逐项校验。演示客服对应陈小雨，其单项权限可由管理员修改。授权申请按模块在内存记录待审批状态，重复申请被阻止；申请不直接授予权限，正式审批与通知需后端接入。

## 修改约定

1. 增加或修改页面、模块、功能、权限或后端对接需求时，同步更新 `function.md` 中对应的页面功能与后端待补说明；新增页面还要在本文件补充界面职责与角色，在 `pages/<页面 ID>.html` 的 section 前添加注释，并把页面 ID 加入 `src/load-pages.js`。
2. 后端数据通过清晰的 API 边界接入，保留 `tenant_id`、`store_id`、`state_version`、`Idempotency-Key` 和来源追溯信息；不要把服务端授权判断移到浏览器。
3. 在发消息、派单、转接、审核和导入等异步操作中区分「请求已创建」与「渠道最终成功」。
4. 注释解释业务原因和接口约束，避免逐行翻译代码；涉及真实 API 时同步更新 `docs/backend-integration.md`。
5. 提交前运行 `node --check src/app.js`、`node --check src/mock-data.js`、`node --check src/admin.js` 与 `node --check src/admin-data.js`，并在浏览器检查工作台、角色切换与主要操作。

## 数据导出页面
- `exports`：客服和公司管理员可进入，按服务端授权选择公司，创建顾客或单条会话导出，查看后台任务状态，下载 Excel 和对话记录。下载携带会话令牌，权限由后端校验。
