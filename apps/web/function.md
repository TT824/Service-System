# 前端页面与功能清单

> 用途：按“页面 → 模块 → 功能 → 后端待补”记录当前原型，供前后端拆分接口、补齐业务规则和验收。各页面结构见 `pages/<页面 ID>.html`，共用外壳见 `index.html`，接口边界见 `docs/backend-integration.md`。

> **整合副本状态（2026-09-24）**：账号密码登录、退出、会话恢复、后端角色映射、坐席状态与心跳、真实会话列表/详情、文本发送、结束会话、转交会话，以及统一知识库的读取与管理员维护已经接入 `End` 后端。其他页面仍按下表的原型状态执行。

> **单公司角色约定**：后端 `platform_admin` 和 `merchant_admin` 在本前端都显示为“管理员”。管理员登录后直接进入管理员中心，并拥有原型中员工数据、员工对比、权限管理、员工分流、聊天记录和操作日志的完整入口。

## 阅读约定

- **界面**：页面上已有展示或操作入口，但可能只展示固定内容。
- **本地演示**：浏览器内有交互，刷新后数据通常恢复；不代表服务端已保存或渠道已执行。
- **待对接**：需要后端、渠道或业务系统提供数据和真实操作。
- 本清单描述当前页面与待补能力。下文“应提供”“需确认”是对接需求，不表示前端已经实现。
- 页面 ID 对应 `pages/<页面 ID>.html` 中的 `<section id="...">`；工作台的群聊、联系人和智能辅助是同一页面内的模块。

> 登录门禁：离开 `login` 页必须先存在经 `/api/v1/auth/session` 校验通过的后端会话（`navigate()` 统一收口），会话失效或退出登录时立即恢复到锁定状态。此前侧边导航、登录页“返回账号中心”和演示角色切换都未校验会话，点击即可进入控制台页面，属于界面门禁缺失，已由 `src/app.js` 的 `applyAccessLock()` 修复。该门禁只负责界面收口，真实数据读写仍由后端按 Bearer 会话校验。

## 1. 客服工作台 `workspace`

| 模块 | 页面上的功能与当前状态 | 后端需补充 / 确认 |
| --- | --- | --- |
| 顶部客服状态 | 登录后在线、挂起、离线状态同步后端，退出走账号登出；SSE 同步本账号接待状态。 | 跨设备会话失效与服务端资格决定最终生效状态。 |
| AI 辅助开关 | 停止 / 开启候选建议；本地切换。 | 保存坐席偏好，停止候选生成但保留消息接入和人工回复。 |
| 顶部指标 | 「今日接待」接后端时显示“—”并注明原因（后端给的是全量会话列表、没有「今天」这个事实，不拿会话总数凑数），演示数据下才按“非昨天”的会话数算；昨日平均首响、候选采纳率等仍是示例值；未下单、未付款、已付款、满意度、3 分钟回复率、转化率等当前显示“—”。可展开补充指标。 | 按客服、租户、授权店铺和时间返回数值、统计口径、更新时间及不可用状态；订单和满意度指标依赖外部数据接入。 |
| 我的会话 | 处理中、已结束分类与搜索；真实列表及当前消息通过 SSE 通知后重新读取。系统自动分配，没有抢单或退池入口。登录后（**进来就拉一次同事目录与会话摘要**，不必先去联系人栏——否则进门只看到客户会话，会以为同事会话不存在）列表里除了客户会话，还按最后消息时间混排**已经有过消息的同事会话**（空会话不列），每行名字后按对方**实际角色**标「客户」「客服」或「平台管理员」（不写死「客服」：内部会话的另一端可能是平台侧），摘要写明最后一条是谁发的（自己发的写「我（角色）」，别人发的写「角色 名字」）；**会话里出现的同事即使不在同事目录里**（对方刚停用、目录请求失败、本机后端是旧构建），也照样按服务端给的名字显示、并且点得开——原先这种情况会退化成没有名字的「同事」且点开是空白面板；点同事行直接进入该同事的内部会话，切回来不会被顶到别的会话上。「已结束」页签只列客户会话，因为内部会话没有结束态。门店脚注显示门店名（查不到才退回 ID）。**平台管理员（不属于任何公司的那个身份）登录后这块列表一条客户会话都不读**：他不在接待名单里，服务端给他读到的每一条客户会话都是 `canReply=false` 的只读会话（回复区整块隐藏），留着只会造成「看得到消息、发不出去」的误读；所以这个身份的工作台只列与客服的内部会话，标题行写明当前在跟哪家公司说话（公司名取自启动时选定的租户），「已结束」页签恒为空。空列表时提示去「联系人 → 团队」选客服开始，而不是留一句「当前没有会话」。 | 未读数（客户与同事消息都还没有已读未读）、分页与服务端统计计数仍待补；客户会话行的发送方摘要前缀依赖读过详情，列表接口不带消息方向；退出或鉴权失效停止实时更新。 |
| 联系人 | 与“我的会话”切换；团队、群聊、买家、黑名单分类；按姓名或分组搜索，分组展开 / 收起。点团队成员姓名直接进入与该同事的一对一内部会话（有历史时列表显示最后消息时间并高亮当前联系人）；点买家联系人跳转到对应会话：先按联系人记录的会话 ID 找，找不到再按客户姓名找（登录后会话列表会被真实后端数据替换，演示数据里的 ID 往往已经不存在），两者都找不到时提示“当前没有可打开的会话”，不静默失败。新建分组和调整分组属于目录维护：普通客服看不到「＋ 新建分组」和行内「⋯」，只有商家管理员及以上可用；客服即使被其它入口触发也会被拦下并提示无权。**登录后团队一栏改用服务端同事目录（`GET /internal-chat/peers`），分组就是门店**（不再有演示里的售前 / 售后客服分组），默认展开，点标题即可收起、再点展开（CHG-20261006-05）；此时不显示「＋ 新建分组」与行内「⋯」，因为门店分组不可维护。展开 / 收起是页面内的浏览状态：**点过的分组按用户的意思记住**——搜索、清空搜索、切栏目再切回都不会把它弹回默认；只有从没点过的分组才走默认值（搜索时全部展开，登录后团队栏的门店分组默认展开）。刷新或换账号回到默认，未接后端。演示名单（陈小雨、李明等）只在未连后端时展示——两套名单混着显示会出现点了不存在的同事。**同事目录里除本公司同事，还有平台管理员**（不属于任何公司的那个身份，`GET /internal-chat/peers` 一并返回，每家公司都看得到）：他不挂在任何门店上，因此单独归到「平台」分组、详情写「平台管理员 · 平台侧」，而不是被当成一个「未分配门店」的同事。点他就开一条与平台侧的会话——平台侧发得下来，客服也回得上去。买家分组与黑名单仍是演示数据。 | 已接通同事目录查询；仍待补：买家的联系人 / 分组 / 黑名单建模与查询、创建、移动、可见范围与版本控制。分组维护接口须按角色（普通客服只读）和租户范围在服务端校验，不能只依赖前端隐藏控件。黑名单的添加、解除和对接行为需另定规则；团队栏是否要恢复「可维护的分组」需要先定后端模型，不能拿门店当分组改。 |
| 客户会话 | 显示客户、渠道、店铺、接待人、会话状态、消息历史和来源；结束会话与转交会话均已接后端。「转交」只在有转移动作时出现：正在接待的会话（本人接待）和接待人已下线、可由管理员或同店铺坐席接手的会话，按钮才显示；待接入（尚未认领）与已结束会话不显示。点「转交」先取服务端返回的可转交名单（同租户内在线且可接单的同事，排除自己，名单为空时提示“当前没有在线且可接单的同事”），选择后提交立即改派；名单与「谁可以接手」都由服务端按同一套规则给出，前端只收口入口，因此不会出现能选却被拒的选项。**客服气泡按接待人画脸和署名**（CHG-20261006-04）：消息行不带发送人，只记「谁在接待」（`assignedMemberId`），所以查看同事接待的会话时，气泡上的头像与名字都是那位同事的，而不是当前登录者的；接待人不在同事目录里（或还没人认领）时退回当前账号那张。**客户那一侧没有头像可取**，仍画姓名首字——企业微信侧不向我们提供客户头像。 | 会话详情与消息游标分页；转交 / 结束提交 `state_version`，处理并发冲突并推送归属变化。可转交名单已由 `GET /api/v1/conversations/:id/transfer-targets` 返回；列表项携带显示名和手头会话数，供选择时参考负载；入口可见性读会话详情的 `canTakeOver`。同一份详情还带 `replyWindow`，供上方的外发提醒渲染；分配历史由 `GET /api/v1/conversations/:conversationId/assignments` 返回。 |
| 外发提醒 | 接后端：显示服务端给出的 48 小时回复窗口截止时间与剩余外发额度（会话详情返回的 `replyWindow`），并区分「窗口未开启（客户还没发过消息）」「窗口已关闭」「本窗口额度用尽」三种情况；额度与截止时间随会话变化、每次打开会话重新读取。原来的示例文案与写死的 09月24日 截止时间只在未连后端的原型模式出现。 | 按渠道真实规则返回窗口截止、可发送额度、禁发原因；发送任务创建与渠道最终成功分开显示。窗口判定与服务端拒收外发用的是同一份规则。 |
| 回复编辑器 | 文本回复接真实 API，Enter 发送、Shift+Enter 换行；候选选用或编辑后保留来源。显示渠道投递状态。**回复区（输入框、发送按钮与上面的回复工具栏同属一块 `.composer`）只在当前选中了一条会话时显示**：没有选中会话、会话已结束或 `canReply` 为 false 时整块隐藏，只留「当前分类暂无会话」。因此名下没有客户会话的客服账号一登录就是空的下半屏——那是没有会话可回，不是工具栏被移除（有前端断言钉住两种状态）。 | 媒体上传外发已接通（客户会话见「回复工具栏」一行）；发送失败后的重试入口仍待补；服务端负责幂等与发送权限。 |
| 回复工具栏 | 图标按钮悬停显示说明：表情、截图、图片、视频、文件、快捷短语、商品链接、邀请下单。图片 / 视频 / 文件一次选择一个，按会话暂存，支持预览名称与移除；截图提示粘贴。**附件已经是真的能发给客户了**（自 `CHG-20261006-09`）：点发送时把文件作为 `multipart` 的 `file` 字段提交给 `POST /conversations/:id/messages/media`，服务端在同一次请求里校验 → 写下我们自己那份字节 → 上传企业微信换 `media_id` → 写消息行 → 进发送队列，所以**没有「先上传、再发送」两步**（企微的素材句柄三天过期，中途不能停在浏览器里，这一点与内部会话的附件不同）。发送期间草稿标「（发送中…）」、发送按钮禁用、移除按钮拒绝（这一份字节已经在路上，撤掉只会留下「按了发送但界面什么都没有」的错觉）；成功后撤掉草稿并重读会话，失败把草稿留在原处、原因和内部会话一样按 `error.message` + `error.details` 拼出来。**附件与文字不能一起发**：渠道的媒体消息没有说明文字字段，服务端也拒收，前端在提交前拦住并要求分两条发，不静默丢掉打好的正文。**客户发来的图片也真的显示出来了**：详情里的 `messages[].media` 加上这一次现签的 `mediaUrls[id]`，图片内嵌、视频给播放器、其余给带文件名的下载链接；地址十分钟寿命，每次回读重新签发；**签不出地址时退回服务端存下的那句占位文字**（「[图片消息]」），不画一个必然裂掉的图，也不装作这条消息什么都没带。有可渲染媒体的气泡**不再显示正文**——那段文字是给列表预览和导出读的（图片是占位串、文档就是文件名），气泡里已经有图 / 播放器 / 下载链接了。商品和下单链接仍是示例，需人工确认发送。 | 媒体上传已接通（见「客户会话媒体消息契约」）；仍待补：**发送失败后的重试入口**、视频时长的服务端校验、病毒扫描、渠道能力声明（`ChannelCapabilities` 装不下「支持视频 / 文件」，设置页声明不了这两类）；获取有效商品、规格和下单链接（当前是示例）；返回最终外发状态。客户端预检的限制与服务端一致：**图片 10 MB（只收 PNG / JPEG / GIF）、视频 10 MB（只收 MP4）、文件 20 MB**，但**真正说了算的是服务端**（它按内容类型判定并再判一次，超限或类型不符时拒绝、把原因放在 `details` 里返回）；文件选择器的 `accept` 也按同一份清单收窄，避免选中一个必然失败的 WebP。**未在真实企业微信账号上验证**。 |

| 登录：方式切换 | 账号密码、验证码登录、注册账号；当前只切换表单文案。密码框右侧的显隐按钮常驻（原生「眼睛」只在聚焦或已有内容时出现，时有时无，所以换成了固定控件）：登录与注册都是密码类型，按钮可显隐；验证码是明文，按钮隐藏；切换登录方式或退出后会收回明文，退出时清空密码框。密码登录的失败按服务端错误码分别提示：凭据不对是「账号或密码不正确」，连续输错触发的临时锁定单独说明（**连续 3 次**错密码后锁定 15 分钟，期间即使密码正确也会被拒绝；登录成功会把已累计的失败次数清零）。 | 注册、密码 / 验证码校验、令牌 / 会话管理、错误次数与安全限制。 |
| 登录：找回密码 / SSO | 页面有入口，目前只提示演示；提交也只跳转账号中心。 | 密码重置、验证码时效、SSO 登录和账号绑定。 |

## 跨页面后端规则

1. **身份和授权**：每次请求都由服务端核对登录身份、`tenant_id`、授权 `store_id`、员工角色及模块权限。数据列表和详情都要过滤；不能只限制前端入口。
2. **异步状态**：发送消息、商品导入、索引、话术审核等区分“请求已受理”与“最终成功”；返回任务 / 消息 ID，并通过查询或 WebSocket/SSE 更新结果。
3. **并发和重试**：会话转接 / 结束、权限与分流修改携带版本号；可重试写操作使用 `Idempotency-Key`；冲突返回可识别错误和最新版本。
4. **列表查询**：联系人、会话、商品、FAQ、短语、聊天记录和操作日志需要店铺范围、筛选、排序、分页；消息与日志优先游标分页。
5. **隐私与审计**：客户与聊天记录默认脱敏；查看原文、导出、修改权限和分流要按操作授权并留审计记录。
6. **不可用数据**：订单、满意度和转化等未接入时返回明确的 `unavailable` 状态及原因；前端显示“—”，不使用演示数字充当生产统计。
7. **错误反馈**：统一返回稳定错误码、可读说明和 `request_id`；403 对应“暂无权限”，版本冲突提示刷新，网络失败允许安全重试。

## 需要共同确认的产品问题

- 付款人数 / 金额归因：同一客户多订单、跨员工转接、退款 / 取消、跨店订单如何计入。
- 平均响应、首次响应、3 分钟回复率：从哪条客户消息开始计时，自动回复、挂起、离线和跨日如何处理。
- 满意度：评价采集渠道、有效样本、未评价会话和统计最小样本量。
- 自动分流：可参与资格之外的负载、优先级、店铺匹配、超时重分配和无人在线的处理。
- 管理员权限：全部与单项权限能否按店铺细分；谁可授权谁；聊天记录原文 / 导出是否单列权限。
- 联系人与内部群：买家分组归属、黑名单效果、建群资格、成员变更和消息保留期限。

## 数据导出 `exports`
- 左侧导航提供数据导出入口，客服和公司管理员均可访问；公司列表来自真实授权目录。
- 支持按关键词、UTC 日期范围创建顾客导出，或选择真实会话导出单条对话。两个口径的产物不同：顾客口径是名单（Excel + 顾客名单文本，不含对话），会话口径是聊天记录（Excel + 对话记录文本，含每条消息）。表单随范围变化给出说明，避免在名单里找对话。
- 日期框默认填「上月本日 → 本日」，按 UTC 自然日算（与提交时的 UTC 边界同一口径），上月没有这一天时取上月最后一天（3 月 31 日 → 2 月 28 日，闰年为 2 月 29 日）；每次打开只在操作者没改过时跟着日历往前挪，改过就保留他的选择，清空仍然表示不筛日期。
- 工作台会话的「导出对话记录」按钮把当前会话带到本页：自动选中「单条会话记录（含对话）」和该会话，创建仍由操作者点击；会话不在当前公司可导出范围内时明确提示。
- 创建只代表请求已受理。任务列表显示排队、生成中、已完成、失败、创建及完成时间、行数与错误，并标注每条任务的来源（顾客 / 会话）；页面存在未完成任务时每 4 秒更新，离开页面停止更新。
- 仅成功且存在产物的任务可以下载；按钮按口径命名（顾客导出为「Excel / 顾客名单」，会话导出为「Excel / 对话记录」）并带内容说明。下载请求携带登录令牌及公司范围。
- 后端要求：API、数据库和导出 Worker 正常运行；任务查询返回最近任务，导出量限制及权限由服务端执行。本功能不包含订单或付款数据导出。
